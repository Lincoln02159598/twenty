# 扩展机制 (扩展机制)

## 分析快照

- 分支：`main`；HEAD：`4dbc5a567ef4f8465ca69632cc9fec8eff388732`
- 工作区状态：任务开始时 clean；本任务仅新增 `./docs-analysis/`。
- 子模块状态：无。
- 分析范围：Apps 框架、工作流 action、消息/连接器 driver、MCP、升级命令、cron、feature flag、code interpreter、event/subscription 等。

## 证据分类

- `[Evidence]` / `[Inference]` / `[Unknown]`（同前）。

## 核心结论

- `[Evidence]` **Twenty Apps 是真实的运行时插件系统**（非仅构建期）：第三方 App 可声明 object/field/view/page-layout/widget/navigation-menu-item/front-component/logic-function/connection-provider/agent/skill/role/index，安装时同步进 workspace metadata，运行时按 trigger 在 Lambda/本地子进程执行，且 Slack 即以此形态存在。
- `[Evidence]` 此外存在多个**有限的、枚举式扩展点**（工作流 action factory、消息/连接器 driver、升级命令、cron job），它们可加新实现但集合是封闭枚举或目录约定，**非通用插件市场**。
- `[Evidence]` 无"运行时动态加载任意第三方 npm 包进主进程"的机制；用户代码隔离在 Lambda/子进程。

---

## 1. Twenty Apps 框架（核心扩展机制）

### 扩展点名称：Application / App

- **接口/类型**：`Manifest`（来自 `twenty-shared/application`）；SDK authoring API `defineObject`/`defineField`/`defineFrontComponent`/`defineLogicFunction`/`defineApplication`/`defineConnectionProvider`/`defineAgent`/`defineSkill`/`defineRole`/`defineNavigationMenuItem`/`definePageLayout` 等。
- **注册方式**：App 代码经 `twenty-sdk` CLI 构建/打包（`logic-function-resource/services` + `copy-builder.ts`/`create-zip-file.ts` 产 Lambda zip）；`application.config.ts` 声明 `displayName`/`serverVariables`（含 secret）；经 `app publish/install/deploy/uninstall` 注册到 marketplace。
- **加载时机**：工作区安装 App 时 `ApplicationInstallService.installApplication` → `ApplicationSyncService.synchronizeFromManifest` → 26 个 `from-*-manifest-*` converter 产 workspace metadata 迁移 → 经 `workspace-migration` 同步成 DDL/数据。证据：`application-sync.service.ts:56-119`、`application-manifest/converters/`。
- **生命周期**：install / upgrade / stop / uninstall / marketplace / development / key-value / variable / oauth（对应 `engine/core-modules/application/*` 子目录）。证据：目录列表。
- **可访问资源**：经 logic function 内 SDK（读 workspace 记录、调 connection provider、发 network 请求等）。
- **权限边界**：logic function 在 **AWS Lambda（subhosting，role/layer bucket/S3）** 或**本地子进程（预构建 bundle + deps/sdk layer）** 或 `DisabledDriver` 执行——隔离依赖运行时边界，而非主进程沙箱。证据：`logic-function-driver.factory.ts:46-112`、`drivers/{lambda,local,disabled}.driver.ts`。
- **调用路径/触发器**：
  - route trigger（`server-route-trigger.controller.ts`，公开 `POST /webhooks/server/:id`）。
  - cron trigger（`triggers/cron/cron-trigger.cron.job.ts`）。
  - database-event trigger（`triggers/database-event/call-database-event-trigger-jobs.job.ts`）。
- **示例实现**：`twenty-apps/public/slack/`（完整 Slack 助手 App）、`twenty-apps/fixtures/minimal-app/`（每种原语各一）、`twenty-apps/examples/document-generator/`（文档生成）。
- **稳定性**：`[Evidence]` 有 fixtures + 公共 Slack App + 各原语 spec 测试作回归；converter 与 metadata 迁移强耦合（metadata 模型变更需同步 converter）。
- **预装机制**：`ApplicationRegistrationEntity.isPreInstalled=true` 的 App 在每个工作区创建时自动安装。证据：`pre-installed-apps.service.ts:50-67`。

### 满足度自检（真实插件系统判据）
- 可加新实现：✅（SDK define* + CLI publish）。
- 入口发现/注册新实现：✅（manifest sync + 26 converter + isPreInstalled 自动装）。
- 调用方依赖抽象：✅（server 经通用 `server-route-trigger`/trigger/lifecycle hook，不 hardcode 具体 App）。
- 生命周期明确：✅（install/upgrade/stop/uninstall）。
- 错误隔离明确：✅（Lambda/子进程）。
- 实际示例/测试：✅（Slack/minimal/document-generator + spec）。

`[Inference]` Caveat：App 部署经 Twenty 自有构建/打包管线（Lambda zip），故"声明式(构建期创作) + 运行时动态加载执行"两者并存。

## 2. 工作流 Action（封闭枚举扩展点）

- **扩展点**：`WorkflowActionFactory`（`workflow-action.factory.ts:54-100`），**固定 18 种**：CODE/LOGIC_FUNCTION/SEND_EMAIL/DRAFT_EMAIL/CREATE_CALENDAR_EVENT/CREATE|UPSERT|UPDATE|DELETE|FIND|PICK_RECORD/FORM/FILTER/IF_ELSE/ITERATOR/HTTP_REQUEST/AI_AGENT/EMPTY/DELAY。
- **注册方式**：在 factory 内显式注册（非动态发现）。
- **可扩展性**：`[Inference]` 加新 action 需改 factory + 实现 action 类，**非开放扩展**。
- **AI 可调用工具**：`workflow-tools/tools/`（约 20 个，如 `create-complete-workflow`/`activate-workflow-version`/`update-logic-function-source`）——让 AI Agent 构建/编辑工作流。
- **Evidence**：`modules/workflow/workflow-executor/factories/workflow-action.factory.ts:54-100`、`workflow-tools/tools/`。

## 3. 消息通道 / 邮件 Driver（目录约定扩展点）

- **扩展点**：`MessageChannelType` = EMAIL/SMS/EMAIL_GROUP（`twenty-shared/src/types/MessageChannelType.ts:1-5`，**无 Slack**）。
- **driver 约定**：`modules/messaging/{message-import-manager,message-folder-manager,message-outbound-manager}/drivers/{gmail,microsoft,imap,smtp,inbound-email,email-group}`。
- **可扩展性**：`[Inference]` 加新邮件 provider = 新 driver 目录 + 接口实现；通道类型本身受 enum 约束。
- **Evidence**：`MessageChannelType.ts`、driver 目录。

## 4. Connected Account Provider（enum + driver + App provider）

- **扩展点**：`ConnectedAccountProvider` = GOOGLE/MICROSOFT/IMAP_SMTP_CALDAV/OIDC/SAML/EMAIL_GROUP/**APP**（`ConnectedAccountProvider.ts:1-9`）。
- **OAuth2 driver**：仅 google/microsoft（`connected-account/oauth2-client-manager/drivers/`、`refresh-tokens-manager/drivers/`）。
- **App 连接器**：`APP` 让 connected account 由 App 声明的 `ConnectionProvider` 支撑（`connected-account.entity.ts:91-98` 关联 `ConnectionProviderEntity`；App 侧 `public/slack/src/connection-providers/slack-connection.ts`；lifecycle hook `connection-provider-lifecycle-hook.service.ts`）。
- **Evidence**：`ConnectedAccountProvider.ts:1-9`、`connected-account.entity.ts:91-98`。

## 5. MCP（Model Context Protocol）扩展面

- **扩展点**：`/mcp` 端点（`McpModule` + `McpMethodGuardMiddleware`），含真 SSE。
- **可扩展性**：`[Inference]` 面向 AI 工具（如 Claude）以 MCP 暴露 CRM 能力；工具集合由 server 内部定义。
- **Evidence**：`engine/api/mcp/controllers/mcp-core.controller.ts:79-82`、`app.module.ts:77,161-163`。

## 6. 升级命令（实例/工作区，注册表扩展点）

- **扩展点**：`@RegisteredInstanceCommand`/`@RegisteredWorkspaceCommand`，由 `UpgradeCommandRegistryService.onModuleInit` 经 `DiscoveryService` 自动发现并分桶。证据：`upgrade-command-registry.service.ts:74-92`。
- **生成**：`database:migrate:generate` 自动产 up/down SQL 并注册。
- **约束**：`[Evidence]` 禁止删除/重写已提交命令的 up/down（`UPGRADE_COMMANDS.md`）。
- **可扩展性**：加新命令 = 新文件 + 装饰器（开放，受版本规范约束）。

## 7. Cron Job / 队列 Job（注册扩展点）

- **扩展点**：cron job（server 注册，worker `DISABLE_CRON_JOBS_REGISTRATION`）+ BullMQ job processor（`JobsModule`，17 队列）。
- **可扩展性**：加新 cron/job = 新文件 + 装饰器注册。
- **Evidence**：`message-queue.constants.ts:5-23`、`jobs.module.ts:1-51`、`docker-compose.yml:61-71`。

## 8. Feature Flag / 配置扩展

- **扩展点**：`FeatureFlag` 实体 + `FeatureFlagModule`；config 经 `TwentyConfigService`（env+DB）。
- **可扩展性**：`[Inference]` 运行时开关，非代码插件。
- **Evidence**：`engine/core-modules/feature-flag/`。

## 9. Code Interpreter / Logic Function（执行扩展）

- **扩展点**：`CODE_INTERPRETER_CONFIG` 配置组 + Logic Function driver（Lambda/Local/Disabled）。
- **可扩展性**：用户/App 代码经隔离 runtime 执行（与 §1 App logic function 同机制）。
- **Evidence**：`logic-function-driver.factory.ts:46-112`。

## 10. Event / Subscription（事件扩展）

- **扩展点**：`SubscriptionService` 三类 channel（core/eventStream/agentChat）+ `object-record-event-publisher`/`metadata-event-publisher`/`agent-chat-event-publisher`。
- **可扩展性**：`[Inference]` 发布者可加；订阅经 GraphQL Subscriptions。
- **Evidence**：`subscription.service.ts:30-131`。

## 11. 不存在 / 名义存在的扩展（澄清）

- `[Evidence]` **无通用"运行时动态加载第三方 npm 包进主进程"机制**——所有用户/App 代码隔离在 Lambda/子进程。
- `[Evidence]` **无独立 webhook 出站投递框架**（仅 workflow `HTTP_REQUEST`）。
- `[Evidence]` 消息通道 enum **不含 Slack**（Slack 是 App，不是内置通道）。
- `[Inference]` 工作流 action、消息通道类型为**封闭枚举**，非开放插件。

## 当前限制

- `[Evidence]` App logic function 强依赖 AWS（Lambda subhosting）或本地子进程 runtime；自托管需配置 `LOGIC_FUNCTION_TYPE`。
- `[Inference]` converter 与 metadata 模型强耦合，metadata 重构会破坏已发布 App。
- `[Evidence]` front-component 经 `twenty-front-component-renderer`（`@remote-dom/react`）渲染，类型对齐有已知 pin（`@remote-dom/react/@types/react`）。

## 已确认事实 / 合理推断 / Unknown

- `[Evidence]` Apps 是真运行时插件；其余多为封闭枚举/目录约定扩展点。
- `[Unknown]` App 市场(marketplace)的实际分发/审核机制细节（`application-marketplace/` 未深挖）。

## 批判性评估 / 建设性改善建议

- `[Recommendation]` 为 App manifest 版本化与 converter 兼容性加显式策略（避免 metadata 重构静默破坏已发布 App）。优先级：高；难度：高。依据：`application-manifest/converters/` 强耦合 metadata。
- `[Recommendation]` 文档显式区分"封闭枚举扩展(action/channel)"与"开放插件(Apps)"，避免开发者误判可扩展性。优先级：中；难度：低。
